# Babylon Design Context

## Design Context

### Users
Crypto-native early adopters, Web3 prediction-market enthusiasts, Farcaster-adjacent audience. They have wallet and OAuth habits, expect bright branded buttons on auth, and are impatient with heavy chrome. The login surface is their first impression of Babylon. It needs to feel like a game portal, not a SaaS dashboard.

### Brand Personality
Bold, gamified, a little irreverent. Social-first. "Playful dark mode" with some retro/arcade influence elsewhere in the product. Three words: confident, playful, direct.

### Aesthetic Direction
- Dark mode by default. High-contrast type, restrained palette inside the auth card.
- OAuth buttons (Google, Discord, X with official brand color icons) are already the visual source of truth. Everything else on the login card must match their rhythm, width, height, and radius.
- **Anti-references:** no widget chrome, no duplicate headings, no stacked "Sign in" treatments, no SaaS onboarding vibe, no emoji-as-icon (the literal 🔑 emoji next to "Passkey" is slop).
- Keep brand color usage where it already lives (primary CTAs, links). Everything else is neutral border + subtle hover.

### Design Principles
1. **One card, one hierarchy.** A single title, a single stack of auth options. No nested mini-screens.
2. **Match the OAuth row.** Every auth button has the same height, width, radius, spacing, and icon sizing as the existing Google/Discord/X buttons. Email and passkey are full-width rows in the same family, not a cramped two-up split.
3. **Progressive disclosure, not parallel stacks.** Show a clean menu of options. The email input appears only when the user chooses email, the passkey flow only when they pick passkey. No input fields sitting open and inert on first paint.
4. **No ornament.** No widget logos, no decorative dividers, no emoji stand-ins for icons. If an icon goes next to a label, it is a real icon.
5. **State transitions are quiet.** Loading, success, and error states live inline and never reshuffle the card layout.

### Existing Style Sources
- `apps/web/src/components/ui/button.tsx` is the single Button component. `variant="outline"` defines the OAuth row look.
- `apps/web/src/components/ui/dialog.tsx` is the modal shell.
- `apps/web/src/components/auth/LoginModal.tsx` is the page being refined.
- Token stack: Tailwind + CSS variables (`--primary`, `--border`, `--muted-foreground`, `--destructive`, `--background`).
